# Vaultroom implementation plan

[Open the interactive mock](index.html). The browser demo starts unlocked with fictional entries and keeps edits in memory until reload. Import uses one fictional record and backup previews the interaction. For a localhost origin, where the browser can offer clipboard access, run `python3 -m http.server 8765 --bind 127.0.0.1 --directory mock` from the repository root and visit http://127.0.0.1:8765/.

## What the current application provides

[FastAPI](../secure_credentials/src/api/server.py) offers status, unlock, lock, metadata listing, and retrieval. Retrieval requires the entry's own credential password. The current lock call revokes all sessions. [VaultGuard](../secure_credentials/src/api/vault.py) serializes access to the open KeePass handler inside a single process. The [KeePass backend](../secure_credentials/src/keepass_backend.py) already implements desktop add, edit, and delete operations that save to disk. The browser should build on that model and preserve access to existing records.

## What to ship and why

| Experience | User value | How to supply it |
| --- | --- | --- |
| Search, types, favorites, tags and a detail pane | Find an entry and see its context without opening a series of dialogs. | Connect the metadata list first. Add a versioned projection keyed by the KeePass entry UUID. Store favorites, tags, and display metadata in the encrypted vault. Retain legacy type labels and map unknown types to Other. Keep protected content out of search results. |
| Reveal and copy | Use a credential without exposing it on screen by default. | Keep entry-password verification on the existing retrieval path and clear the input after submission. Map 401 to the locked screen and 429 to a retry countdown. Hide the rendered value after 15 seconds, on selection or tab changes, and on lock. Copy on deliberate user action and report clipboard errors. Treat clipboard clearing as best effort and avoid overwriting unrelated clipboard contents. |
| Lock screen, countdown and settings | Know when access ends and choose a usable idle policy. | Display the server's session deadline from status and authenticated responses. Recheck on tab return and synchronize lock across tabs. Validate configurable timeout bounds on the server. Make the scope of the current global lock explicit, or implement separate current-session and global actions. Clear drafts, data in the page, and in-flight requests when locked. |
| Create, edit and delete | Manage the vault from the web and stop switching to the desktop app for routine changes. | Add authenticated create, patch, and delete routes keyed by UUID. Reuse existing per-entry cryptography and verification. Require confirmation for deletion, retain encrypted history or an undo path where supported, and use revision checks for stale edits. Preserve legacy fields and distinguish metadata-only edits from secret replacement. |
| Password generator | Replace weak credentials directly from a new or edited entry. | Generate on the device with browser cryptographic randomness. Allow configurable length, compatibility options, and insertion into the form. Keep generated values out of telemetry, activity, and browser storage. |
| Health review queue | See what to rotate or review and jump straight to the relevant entry. | Start with manual review flags and rotation dates stored as encrypted metadata. Record the resolution date. Compute password strength only for authorized secrets and in transient memory. Treat API key scope as a manual review until an issuer-specific integration can verify it. |
| Activity | Verify when the vault was locked, entries were changed, or retrieval was requested. | Record server-side events with time, action, outcome, and an opaque reference. Gate history to authorized sessions and set a retention period. Label copy or reveal as client-reported if tracked. Keep values, passwords, and sensitive entry labels out of logs. |
| Import preview and encrypted backup | Move data with clear duplicate handling and recover after a failed change or drive loss. | Start with encrypted KDBX snapshots and exercise restore against a scratch vault. Build a bounded, authenticated import staging flow with explicit field mapping, duplicate resolution, and a confirmed commit. Discard staged plaintext on cancel or expiry. Keep encryption and per-entry protection explicit in the import flow. |

## Delivery order

1. **Read and retrieve.** Integrate the responsive workspace with existing endpoints. Keep the public API compatible. Cover long names, legacy types, keyboard navigation, wrong entry passwords, empty results, expired sessions, and clipboard failures.
2. **Safe writes and backup.** Establish a single writer across desktop, API, and sync processes before enabling web edits. Serialize mutations, compare revisions, save and validate a staged KDBX in the same filesystem, then atomically replace the live file. Reopen from disk after a failed mutation and publish a success response only after the write commits. Confirm an encrypted snapshot can restore both the KDBX and per-entry credentials before releasing write support.
3. **Organization and operations.** Persist favorites and tags, add the generator, show durable activity and actionable rotation findings, and release staged import once atomic commits and backup are verified.
4. **Release checks.** Run against a copy of a legacy vault. Exercise two tabs, two concurrent edits, desktop or sync conflicts, interrupted saves, rollback, restore, and session expiry during a write. Check at phone and desktop sizes using keyboard and screen reader interaction. Verify that secret values stay out of metadata, caches, logs, and rendered markup while masked.
